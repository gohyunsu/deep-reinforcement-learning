RL 실험과 벤치마크

RL 알고리즘 비교에는 최종 성능(asymptotic performance)과 표본 효율(sample efficiency)을 구분해야 한다. 학습 환경에서의 보상뿐 아니라 별도 평가 에피소드의 return, 학습 곡선, 여러 난수 시드의 분산을 보고한다. 같은 상호작용 수인지 gradient update 수인지 기준을 명시하지 않으면 데이터 효율 비교가 성립하지 않는다.

벤치마크는 표준화된 환경과 과업으로 비교의 재현성을 높이지만, benchmark 점수가 실제 배치 성능을 보증하지는 않는다. Atari는 이산 행동과 영상 관측, MuJoCo·DeepMind Control Suite는 연속 물리 제어, LIBERO·RoboTwin은 로봇 조작과 과업 전이, RoboArena는 정책 선호 비교 등을 강조한다. 서로 다른 benchmark는 관측·행동·보상·데이터 조건이 달라 한 줄의 순위로 뭉치기 어렵다.

평가 시 학습 시드, environment seed, 정규화 점수, 실패/성공 정의, 코드·환경 버전을 기록한다. 여러 과업 평균만 보고하면 특정 과업의 실패가 숨겨질 수 있으므로 분포나 과업별 결과도 살핀다. 사람의 선호 비교는 주관적이고 평가자·프롬프트에 민감하므로 자동 보상과 함께 해석한다.

Reinforcement Learning

표지에서 이 강의의 주제를 확인하고, 뒤따르는 예시가 어떤 의사결정 문제를 설명하는지 질문을 세워 둡니다.

평가 지표와 환경군

asymptotic return은 충분히 학습한 뒤의 도달 성능, sample efficiency는 같은 환경 상호작용 예산에서 얼마나 빨리 성능에 도달하는지다. DMC·Gymnasium·Atari·MiniGrid는 행동 공간과 시각 복잡도, horizon이 다르므로 지표와 조건을 맞추어 비교한다.

How do we compare RL algorithms?

최종 도달 성능과 같은 상호작용 예산에서의 표본 효율은 다른 질문입니다. 학습 step·환경 step·평가 episode 수를 맞춰 비교합니다.

서로 다른 RL benchmark 점수를 한 순위로 놓기 어려운 이유는?

과업, 상호작용 예산, 관측 전처리, 보상 규모, 평가 episode와 seed가 다르면 점수가 측정하는 능력도 달라진다. 같은 프로토콜에서 학습곡선, seed 변동, 실패 사례를 함께 비교해야 한다.
